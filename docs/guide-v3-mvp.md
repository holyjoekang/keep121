# Keep121 Guide v3.0 — 위치 기반 안전 운영 MVP 재설계
작성: 2026-11-11 · 상태: 제안 / 검증 전

## 제품 원칙
Keep121은 위치 추적기가 아닌 단체 이동 안전 운영 시스템이다. 사람 확인(직접 점호)과 기기 위치(참고 신호)를 분리한다. 태그만 버스에 남아도 출발 완료가 되어서는 안 된다. 미확인·미해결 대응이 있으면 출발을 보류한다.

## 사용자와 현장 흐름
운영자: 기관·행사 생성, 참가자 동의·태그 배정, 담당자 권한 관리.
인솔자: 출발 전 명단·장비 점검 → 탑승 직접 확인 → 미확인자 대응 → 출발 승인 → 자유시간 복귀 점호 → 인계 및 장비 회수 → 종료 보고서.
참가자: 앱 설치 없이 QR/NFC 명찰 또는 담당자 직접 확인 가능. 단, 자동 위치 추적은 별도 단말/수집 경로와 동의 필요.

## 위치 소스 전략
1. 삼성 스마트태그3: 공식 위치 제공 API·계약·상업적 이용 권한 미확인. 삼성 앱 수동 확인만 데모에 반영. 기존 태그 좌표가 Keep121에 자동 전송된다고 주장하지 않는다.
2. 스마트폰: 동의 기반 Traccar Client + 기관 서버 REST/WebSocket PoC. 백그라운드·배터리·권한·통신 중단 시험.
3. 독립형 GPS/LTE: 공식 서버 API와 국내 개통/배터리/위치 갱신 조건을 서면 확인한 후 2차 PoC.
4. BLE: 공개 사양 장비의 근거리 감지 후보. 근거리 감지를 사람 위치·탑승 확정으로 변환하지 않는다.

## 화면 IA
오늘: 행사·참가자·태그 배정 및 운영 상태.
점호: 회차별 직접 확인·QR/NFC·확인 취소·출발 보류.
위치: 기기별 출처, 마지막 원본 관측 시각, 수신 시각, 정보 경과시간, 미수신 표시. 현재 데모는 수동 참고 기록만.
대응: 미확인 → 담당자 배정 → 연락·소재 확인 → 현장 직접 확인 또는 인계.
기록: 이벤트 감사 로그, 장비 회수, JSON/CSV, 종료 보고.

## 데이터 계약 (향후 서버)
location_observation {event_id, assignment_id, source_type, device_id, latitude?, longitude?, observed_at?, received_at, accuracy_m?, provider_status, is_manual, note?}
attendance_check {event_id, round_id, participant_id, verified_by, verified_at, method, revoked_at?}
incident {event_id, participant_id, assignee_id, status, action_log[], resolved_at?}
device_assignment {event_id, participant_id, device_id, assigned_at, returned_at?}
관측 시각과 수신 시각을 혼용하지 않는다. 위·경도 미제공 시 임의 생성 금지. 행사 종료 시 접근권한 회수 및 보관 정책 적용.

## MVP 우선순위
P0: 행사·명단, 장비 배정, 회차별 직접 점호, 미확인·출발 보류, 대응 기록, 종료·내보내기.
P0+: 수동 위치 확인 기록(출처·원본 갱신 시각), 위치와 점호 상태의 분리.
P1: 위치 공급자 어댑터, 스마트폰 자동 수집 PoC, 관측 시각 경과·미수신 알림, 다중 담당자 권한·동기화.
P2: 삼성 공식 연동(승인 조건부), GPS 단말 연동, 지오펜스 참고 경보, 기관 콘솔·보호자 알림.

## 시험 지표와 게이트
위치 성능: 위치 경과시간 분포, 미수신률, 위치 공백, 위치 일치율.
운영 효과: 점호 소요시간, 미확인자 인지/해결시간, 오인 점호, 담당자 조작 부담.
안전 게이트: 미확인 상태 출발 0, 오인·중복 점호 0, 최종 직접 확인 완료 100%. 이는 시험 목표이며 실측 결과가 아니다.
법무: 동의, 미성년자 보호자, 개인위치정보 관련 인허가/신고 해당 여부, 위탁·제3자 제공, 보관·삭제를 전문 검토한다.

## 현재 구현 범위
guide/v2-app.js에 '위치' 탭 및 삼성 앱 수동 참고 위치 기록을 추가했다. 데이터는 브라우저 로컬 저장소에만 보관되며 서버·GPS·삼성 API 연결은 없다. 실제 다기관 서비스로 사용하기 전 인증, 권한, 암호화, 백업, 데이터 수명주기 및 현장 시험이 필요하다.
